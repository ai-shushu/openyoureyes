# 发布流程（开发者用）

## 0. 发布前检查

```
.venv/bin/python -m unittest discover -s tests -v     # 全部通过
```
版本号只改一处：`server/serve.py` 的 `VERSION`，以及 `server/eyes_mcp.py` 的 `VERSION`、`plugin/.claude-plugin/plugin.json` 的 `version`（保持一致，`dev/build_extensions.py` 会检查）。

## 1. Claude 插件

```
.venv/bin/python dev/build_extensions.py      # 生成 dist/open-your-eyes.mcpb（Claude 桌面版扩展）
claude plugin validate .                       # 检查 Claude Code 插件市场配置
```
- **Claude Code**：本仓库就是插件市场（`.claude-plugin/marketplace.json` → `plugin/`）。插件只写本机地址 `http://127.0.0.1:39757/mcp`，用户电脑上不需要 Python。
- **Claude 桌面版**：`open-your-eyes.mcpb` 是一个很小的转接器，用 Claude 桌面版自带的 Node 运行，把消息转给本机 Open Your Eyes；Open Your Eyes 没开时工具仍会列出，调用时提示用户打开程序。

## 2. 安卓 App（可选，电脑端自带）

```
.venv/bin/python dev/build_android.py          # 输出 web/app/openyoureyes.apk 和 version.json
```
- 工具链放在 `tools/android/`（JDK 17、Android SDK platforms;android-34、build-tools;34.0.0），不用 Gradle / Android Studio。
- 签名密钥 `tools/android/release.keystore` 和密码文件**务必备份**：换了密钥，用户手机上的 App 不能直接覆盖升级。
- 升级时同时改 `android/AndroidManifest.xml` 的 versionCode / versionName 和 `BuildInfo.java`。
- `dev/build_app.py` 打电脑安装包前会先编译 App（工具链存在时），App 随电脑端一起分发：手机扫码后从电脑下载安装。
- 已实测：vivo V1818A（安卓 8.1）安装、配对、拍照、封面、实时取景、熄屏待命。

## 2b. Mac 安装包

```
.venv/bin/python dev/make_universal_env.py     # 只需一次：建 .venv-universal（Intel + Apple 芯片的通用依赖）
.venv-universal/bin/python dev/build_app.py    # dist/Open Your Eyes.app、dist/OpenYourEyes-<版本>-mac.dmg、dist/latest.json
```
- 发布一定用 `.venv-universal` 打（通用包，约 33 MB）；用 `.venv` 打出来的只能在 Apple 芯片上运行，只适合自己测试。
- 通用包里 cryptography 固定 48.0.1（49 起没有 Intel Mac 版）。这台开发机没装 Rosetta，Intel 版只检查过每个文件都是双架构，没实际运行过。
- 打包只保留最新一版 dmg（旧的自动删掉）。
- 没有开发者账号时是「本机临时签名」：dmg 里附了「打不开？看这里.txt」，教用户
  `sudo xattr -rd com.apple.quarantine "/Applications/Open Your Eyes.app"`，或在「系统设置 → 隐私与安全性」里点「仍要打开」。README 里也写了。
- 正式发布（需要苹果开发者账号，每年 99 美元）：
  ```
  xcrun notarytool store-credentials t9-notary --apple-id <邮箱> --team-id <团队ID>
  T9_SIGN_ID="Developer ID Application: <名字> (<团队ID>)" T9_NOTARY_PROFILE=t9-notary .venv/bin/python dev/build_app.py
  ```
  脚本会签名（加固运行时）、打 dmg、提交公证并装订。

## 3. Windows 安装包（需要在 Windows 上构建）

```
py -m venv .venv && .venv\Scripts\pip install -r requirements.txt pyinstaller
.venv\Scripts\python dev\build_app.py         # dist\Open Your Eyes\Open Your Eyes.exe
```
再用 Inno Setup 之类的工具把 `dist\Open Your Eyes` 做成安装程序；要避免 SmartScreen 警告需要代码签名证书。
**尚未在 Windows 上实测**：首次运行的防火墙弹窗（需允许「专用网络」）、开机自启、托盘图标都要验证一遍。

## 4. 发布

- 上传：dmg、`latest.json`（Windows 安装程序做好后也传）。`open-your-eyes.mcpb` 已经打进电脑程序里（「连接 AI」一键安装用），一般不用单独发。
- 打包前设置 `T9_RELEASE_PAGE`（下载页地址，必须 https）和 `T9_RELEASE_NOTES`（一句话更新说明），它们会写进 `latest.json`。
- **新版本提示**：`server/serve.py` 里的 `UPDATE_FEED` 填上 `latest.json` 的固定地址（已填：`https://github.com/ai-shushu/openyoureyes/releases/latest/download/latest.json`）。
  已装的程序每 12 小时读一次，发现更新就在窗口顶部提示「去下载」。地址空着就不检查。**第一版发布前一定要填好**，否则这批用户收不到以后的更新提示。
- 国内用户访问 GitHub 慢，可同步一份到国内镜像。

## 已知限制 / 待办

- Windows、Linux 版没有实机测试过。
- 电脑程序只提示新版本，不自动替换（需要用户下载后拖进「应用程序」）。
- 电脑 IP 变了以后：安卓 App 和开着的网页拍照页会在同一网段里找回电脑（认根证书指纹）；网页已经关掉、或电脑换到了另一个网段，要重新扫码。
- 安卓各品牌的「自启动设置」页面路径是按公开资料写的，只在 vivo 上实测过；打不开时会退到这个 App 的系统设置页。
- 安卓签名密钥 `tools/android/release.keystore` 不在 git 里，已在本机备份一份到 `~/Documents/Open Your Eyes 备份/`；还需要再拷到 U 盘或网盘（加密存放）。
